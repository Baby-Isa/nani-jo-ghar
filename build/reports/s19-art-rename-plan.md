# The art renames and ids: Fable's plan (13 Nov), adopted

(The Fable plan, 13 Nov ~00:45, adopted by the orchestrator; the builder's design brief. Summary:)
Target: files assets/art/<namespace>/<piece>.<state>.r<rev>.<ext> (namespace = the id's first part, rev = the registry's; immutable names, the registry hash enforces; keep today's extension). Code names ids only; registry.json is the truth. registry.mjs --map generates js/art-map.js (classic script after js/version.js): live pieces only {files:{id:{state:file}}, meta, was:{oldPath:newPath}}; never hand-edited; a check fails if stale; regenerated after merges, never merged. Runtime resolution (Pages, no build step). Keep ?v= cache-busting. New version: registry.mjs add writes r2 beside r1, promote flips the map, r1 stays one release then sources/art-retired/.
Risks: Cook.Art.url already exists (js/cook/art.js:1057, one arg, data URL, 3 callers): use Cook.Art.file(id, state) and Cook.Art.meta(id), fix the doc. assets/cook paths are also named in css/cook.css, css/shared/word-moment.css, index.html, find.html, snap.html, tidy.html, monsoon.html, js/shared/shelf.js, dress, find, snap and ~15 lab files. Five tables are keyed by path (approved.json globs, retired.json, artcheck-known.json, loadcheck manifests / art.assets globs, 14 meta.json files). data/cook.json has 561 path mentions and three other builders edit it: do not rewrite it tonight. registry.json is 337 KB: never ship it to players. Stale open tabs across a publish ask for old names (a known gap).
Order: Step 0 (one commit, no moves): js/version.js njgV looks the url up in NJG_ART.was first (the single chokepoint: every Phaser load passes its addFile hook; Cook.v is njgV); one script tag in cook.html and each page whose code loads a renamed file; Cook.Art.file / Cook.Art.meta in art.js; registry.mjs rename [--game k] [--dry-run] does git mv and rewrites registry.json, approved.json, retired.json, artcheck-known.json, manifest globs and static css/html references, appending to a permanent ledger data/art/renames.json (registry.mjs show <old path> answers); three static checks in artcheck.mjs: exists (every assets/ path named in js, css, data, html, lab exists or is in was), resolves (every map id/state has a file with the right hash; every file under assets/art/ is in exactly one entry), rawpath (shrink-only known list); tests in registry.test.mjs.
Step 1: renames, one commit per game, sekelo first, chai last; touches only assets/, data/art/*, the map and static references (never station JS/JSON or cook.json path strings), so no conflicts; old paths still load through was.
Step 2: ids, one commit per game, same order: path strings become Cook.Art.file(...), mechanical, no logic changes; the game goes on `migrated`. Merge the integration branch before each game. Leave cook.json art.sprites / art.s02 resolving through was.
Step 3 (later): delete was entries when rawpath reaches zero.
Proof: by bytes: loadcheck.mjs --only cook:<k> --json before and after: the same content hashes, no 404s. Measurements: a node test that Cook.Art.meta(id) equals each replaced constant. Screens: strict shotdiff.mjs at 740x320 and 1280x665, L1 and the top level (the full matrix for sekelo).
Do not rename tonight: char.* (Zafar-only approval), scene.*, shared.*, ui.*, clinic, day, house, lab, proto, parked art, and any file another mode loads (build/reports/art-use.json): list them. Chai renamed last; its approval carries over (same hashes; the tool rewrites approved.json). Rollback: one game per commit. Docs and old reports not rewritten (the ledger answers). Nothing publishes overnight; keep was for a release.
