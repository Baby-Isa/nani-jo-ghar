# S06 round 9 (s06-r9): CK-43, a reply pill tapped while the question is said

Branch `s06-r9` (on `ccr-a7370759-t0lee7` at 9eb14710).

**Cause.** Cook's act logger (`js/cook/flow.js` Cook.boot, was 1938-1953) listened on the Phaser parent and logged canvas taps only. The between-station reply pills (`#choices .choice`, `js/cook/ui.js` UI.choose) are DOM controls. A tap on one was handled at once but never logged as an act. The pills come up when the question's talk resolves, up to about 200 ms before its clip ends. A fair tap in that window broke contract-21, so it broke 1 run in 3.

**Fix.** The logger now listens on Cook's play area (`#stage`). It logs the canvas while its scene takes input, and any live control there (a button or `[role=button]`, not disabled or hidden). That covers the pills and the speakers. The conversation's lines and pills are unchanged. Cook has its own input path, not the shared host's `createInput`, so the fix lives in Cook's one logger. The contract-21 description now names it.

**Probe.** A new driver, `answer-while-asked`, runs on story days. It taps the right pill's word while the question's clip is sounding. If the clip has stopped, it plays the question again from the bubble's speaker and taps once the clip starts. Questions with no clip are skipped. The first red run (ob7) replayed a silent greeting, so it passed without testing the fault. The tightened probe reproduced the break exactly.
