# The evidence loop: every row proven by the game, judged without Zafar

**Why (12 Oct, Zafar):** "fix the game reviewers so they can see and validate all the things they couldn't … I can't be judging all of these things myself." The S04 audit judged 174 rows from whole-screen sheets of one 1366×768 run: 86 were "no evidence" because the run never reached the moment the row is about, showed the wrong game, or the row is about sound, timing or motion. Decision 82.

## The design (speed and tokens first)

1. **An evidence spec per row** — `build/sandbox/data/evidence.json`, keyed by row id. Each row has 1–3 probes:
   ```json
   "SH-49": [{ "flow": "cook:fetch", "path": "hint", "level": 2, "sizes": ["1366x768"],
               "at": "results-words", "after": "bulb", "capture": ["crop:.rs-words", "dom:.rs-words"],
               "expect": null, "note": "a bulb press, then the word review: no tick lost" }]
   ```
   - `flow`, `path` (fair, mistake, hint, takeback, speed1, or a new named driver), `level`, `sizes` (only the sizes the row names; default 1366x768, plus 800x360 when it is about phones).
   - `at`: the moment. A Lifecycle event (`request`, `stage-start`, `stage-end`, `results`), a game test state (`njgTest` / `ctx.test.state` names), a heal debug step id, or `every:<state>` (each time it happens, e.g. every knee turn).
   - `capture`: `shot` (whole screen, last resort), `crop:<selector>` (the element and a margin, the default), `zoom2:<selector>` (2× crop for clipping, fringes, ticks), `strip:<selector>:<n>x<ms>` (a filmstrip of n frames for motion: the bob, a wrap, a fade), `voice` (the text timeline of every line: words, clip, start, end, stage boundaries), `dom:<selector>` (the element's text, for wording, English and Kutchi checks).
   - `expect` (optional): a machine assertion the probe can decide alone (no English word outside "to record" tags; one highlight; bubble tail inside the head box; badge order). A row whose every probe has an `expect` never goes to a reviewer.
2. **Reach every moment.** The sandbox plays only the flows, paths, levels and sizes the specs ask for, and captures at the moment, not at fixed start/mid/end points. A spec whose moment is never reached is a tool failure, reported as such (fix the driver or the spec), never as "no evidence" to a reviewer.
3. **Small evidence.** One compact sheet per row: its words (issue, Check, source line), then at most four crops or filmstrips, and any text captures as text (voice timelines and DOM text are read, not looked at). Crops replace whole screens: about a tenth of the tokens.
4. **Machines first.** `expect` probes decide alone; contract checks (decision 75) stay; the reviewer only gets what needs eyes.
5. **Verdict cache.** A verdict is stored with a hash of the row's words and its evidence bytes (`build/tools/review/data/verdicts.json`). Next time, unchanged evidence keeps its verdict; only changed rows are judged again. A sprint re-judges tens of rows, not hundreds.
6. **Judging in small batches.** 15 rows per reviewer call (Fable, or Opus when Fable is at its limit; never the builder), flaws first, PASS or FAIL with one line, written back by the tool. A FAIL reopens the row; a PASS marks it built with the evidence path (decision 76).
7. **Zafar's list is only what a machine and a reviewer can't judge:** how a family voice sounds, whether something feels right to play. Target: under ten per sprint.

## The commands

```
node build/tools/review/evidence.mjs --plan [--rows a,b | --all | --sprint]   # specs, flows to play, rows with no spec
node build/tools/review/evidence.mjs --run  [...]                             # plays, captures, decides the expect probes
node build/tools/review/evidence.mjs --judge [--batch 15]                     # prints/feeds the batches not in the cache
node build/tools/review/evidence.mjs --apply                                  # verdicts → regressions.md
```
`/review` step 9 (the sprint check) runs these for the sprint's rows; the full list once per sprint close.

## Fable's review (12 Oct)

Read as the future judge, against the 86 "no evidence" lines of the S04 audit and the sheets that produced them (SH-49: twelve whole screens, none the end screen; CLN-100: start/mid/end, one wrap turn). The 86 split roughly: the moment was never reached (40%), a size was never played (20%), sound/timing/motion in stills (20%), the wrong flow was mapped (10%), and the rest are DPR, missing references, tool output not on the sheet, or rows that are really decisions. The design fixes the first two kinds if it is enforced; the changes below are what makes the rest judgeable and keeps the verdicts honest.

1. **No row without a spec, ever.** `--plan` exits 1 on any live row with no `evidence.json` entry (today: all ~350). Seed the specs from the Check column (`regress.mjs` already maps its words to flows and sizes), then hand-edit; `/feedback` writes the spec in the same commit as the row. A row with no spec is not "built".
2. **Reachability before the run, not after.** Every game exports its named moments (the `ctx.test.state` names it can emit, plus `results-words`, `served`, `fold`, `pour`, `fill`, `hearing-test`, …), and `--plan` rejects an `at` that no driver can reach. A new moment is a driver change in the same commit as the spec. The S04 misses (end screen after a bulb, served, fold, pour, tooth fill, the ear's hearing test) are all moments no driver had a name for.
3. **The sheet builder refuses blanks.** After the run, every probe is checked before a sheet exists: the moment fired, the selector matched a visible element, the crop is not uniform, the DOM text is non-empty, a filmstrip actually changed between frames. A failed probe puts the row on `--judge`'s "tool failures" list with the reason; the judge never sees it, and the prompt offers no "no evidence" verdict. A judge who still cannot see the state writes `EVIDENCE: <what is missing>`, which goes to the tool owner, never to `regressions.md` as a FAIL.
4. **Sizes and levels come from the row, not a default.** Rows name 390×844, 844×390, 800×360, 915×375, 1280×800 and 1440×900; "L1–L3", "L4". The plan derives `sizes` and `levels` from the Check text (one panel per level), and fails on a size the sandbox has no entry for. Default for "phone" is 844×390 **and** 800×360; the rotate card is 390×844.
5. **Persisted state and seeds are spec fields.** `profile: fresh | seen | second-play` (clear storage; mark help seen; play once, capture the second time: MAA-13, CLN-60, CLN-118, SH-19) and `want: ["fudino ji chutney"]` or `want: {order: "no dungri"}`: the driver tries seeds (bounded, 20) until the order contains the wanted thing and writes the seed it found back into the spec. Rows about a specific order (SH-01, SH-54, DAAR-16) are otherwise luck.
6. **Zoom means DPR 2, never an upscaled crop.** `zoom2` re-renders the page at `deviceScaleFactor: 2` at the same CSS size and crops. A 190 px tawa in a DPR-1 shot cannot show whether the source is 400 px (MAA-07); upscaling shows nothing. Rows about glows, tints and gold outlines (SH-55, SH-58) add `webgl: true`, because the canvas renderer draws no tints.
7. **Canvas objects need their own crop.** `crop:canvas:<name>` takes the bounding box of a named Phaser display object through the lint's display-list walk (the ladle, the pot, the tawa, the chop ring). A CSS selector cannot find them.
8. **Motion rows: a trace plus a strip, and an `expect`.** `strip` stays for the eye (4–6 frames, labelled with ms), but add `trace:<selector>:<ms>` (position, opacity, transform sampled every 50 ms as a small table). Then "pulses", "bobs", "repeats after each pause", "turns as it goes round" (SH-59, MAA-13, DAAR-11) are `expect` assertions (period, amplitude, repeat count), and the judge only looks at the strip for shape.
9. **Split "ear" rows into which and how.** `which` (what clip, when, in what state, in what order) is machine-decidable from the sound hook: card order against spoken order (SH-08), sizzle only with food on a lit tawa (MAA-11), no voice after stage end, "moves on after a beat" (CLN-83: `stage-end` → next `request` within 300–1500 ms with no button press). Add the player's taps with timestamps to the `voice` timeline so "input live during speech" (SH-20, LNG-07) is a tap at line-start + 200 ms and a state change. `how` (does Mum's clip sound right, speed, naturalness) is Zafar's only, and the voice timeline carries each clip's class (family-ok, tts, silent) so a `how` row never reaches him on a TTS clip.
10. **Kutchi and wording rows are text, never pixels.** Capture the whole visible page's text nodes in reading order, each tagged with its style (grey italic + "to record" = placeholder) and its source (engine sentence, clip id). `expect`: every visible word is in the family lexicon or inside a placeholder; nothing in the "?" pop-up leaks out. Do not use an English dictionary (chai, dai, loon are "English"); use the lexicon. The judge compares the sentence to the form the row names (hakri vs hakro); nobody but Mum judges the grammar (rule 4).
11. **Art and culture rows cache on the asset, not the screenshot.** Key the verdict on the asset file's hash and judge each new or changed asset once, on a fixed checklist (clean edges on cream, style match, no sweets, no religious markers, modest clothing, no retired art). A row that only places an asset reuses that verdict and adds one crop for placement.
12. **References go on the sheet.** `ref:<path | css-token | retired-art id>` pastes the reference (a swatch, the source PNG, the shared ring) beside the crop. CHT-05, ART-02 and every "matches the shared token" row are unjudgeable without the thing to compare against.
13. **Tool output is a capture.** `cmd:<script>` puts a script's stdout on the sheet as text with an `expect` (check_hotspots, check_vessel_meta, load time, the lab debug log). CK-25, CLN-07, CLN-09 and CLN-88 were "no evidence" because the proof lived in a script nobody ran.
14. **Crops lose the room.** A crop of `.rs-words` cannot show a lopsided card (SH-51) or a bubble far from its head. Layout rows get one whole screen at the row's size (scaled to ~800 wide) with the crop rectangle outlined, plus the crop; text, tick and fringe rows get the crop alone. Keep a separate whole-screen "sweep" batch once per sprint (contact sheets, flaws only, no row verdicts): that is where the S04 "Other flaws seen" came from, and crops would have hidden them.
15. **Batches of 8–10, grouped by kind, one PNG per row.** Fifteen rows × four crops is 60 images per call; accuracy drops and the S04 judge was opening full-size shots because the thumbnails were unreadable. Per row: one composite PNG at most 1200 px wide, at most four panels at 1:1 CSS px (a zoom row: one panel), panel labels in large type and repeated as text in the prompt. Text-only rows (wording, voice, timing) carry no image and batch 30 per call. Group a batch by kind (layout, art, motion) so the judge keeps one checklist in mind.
16. **Cache on structure, not pixels.** Hashing the PNG bytes invalidates on every antialias and every "6s" timer badge, so the cache will never hit; hashing only the row's words never invalidates when the game changes. Key = row words + spec + the text captures + a perceptual hash of each panel (dHash, small tolerance, dynamic regions such as timers masked) + the git tree hash of the mode's `js/`, `css/` and `assets/` folders. Store with each verdict the run id, the commit, the reviewer model and the panel it cites, so a PASS can be reopened. Once per sprint close, re-judge a random 10% of cached PASSes with a different model; a disagreement goes on Zafar's list.
17. **Make the judge show its work.** The verdict line must name the panel and what it saw ("PASS: B, L3 wrap crosses the kneecap, 6 turns") before the verdict; a PASS that cites nothing is rejected by `--apply`. The tool records the judging session and refuses the builder's.
18. **Keep decisions out of the loop.** Rows that wait on Zafar's yes or an unbuilt alternative (CLN-122, CLN-61's layout A) are tagged `needs-decision` in the Check column and go to `docs/status.md`, never to a sheet.
19. **One run, not two.** Put the probe captures into the sandbox's recorder (at each named moment it runs the specs that ask for it), so the gate's run is the evidence run and `--run` only plays the (flow, level, size, profile, seed) combinations the gate lacks. Two 1 h 50 min passes per sprint is the budget the design is trying to save.
